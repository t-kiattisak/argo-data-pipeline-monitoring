# Observability & Monitoring Specification

This document defines the standards for monitoring, logging, and incident alerting across the batch data pipeline.

---

## 1. Structured JSON Logging Specification

All containerized pipeline processes must output logs to `stdout` formatted as single-line **JSON Lines (JSONL)** to enable seamless ingestion by log collectors (such as Fluentbit or Logstash) into Elasticsearch.

### JSON Schema Specification:
| Field | Type | Description / Example |
| :--- | :--- | :--- |
| `timestamp` | string (ISO-8601) | `2026-09-18T01:05:23.142Z` |
| `level` | string | `INFO`, `WARNING`, `ERROR`, `CRITICAL` |
| `service` | string | `batch-data-extractor` |
| `dataset` | string | `DEVICE_TELEMETRY` or `ORDER_EVENTS` |
| `stage` | string | `EXTRACT_DB`, `WRITE_CSV`, `UPLOAD_S3`, `POST_WEBHOOK` |
| `batch_id` | string (UUID) | Unique identifier per execution cycle |
| `export_date` | string (YYYY-MM-DD) | Partition date of the dataset |
| `row_count` | integer (optional) | Number of extracted records |
| `duration_ms` | integer (optional) | Stage execution duration in milliseconds |
| `message` | string | Human-readable event description |
| `error_details` | object (optional) | Exception type, message, and traceback |

## 2. Argo Workflow `onExit` Email Alerting

The `onExit` hook serves as a container-lifecycle fail-safe mechanism managed directly by the Argo controller.

### Failure Detection Scenarios:
- **Application Failures:** Database timeouts, S3 permission rejections, and API Gateway failures.
- **Infrastructure Faults:** Container OOMKilled events, node evictions, and SLA deadline breaches (`activeDeadlineSeconds`).

### Sample Email Alert Template:
```text
Subject: [CRITICAL ALERT] Data Pipeline Failed: batch-data-extractor-20260918-0100

======================================================================
PIPELINE EXECUTION FAILED
======================================================================
Workflow Name : {{workflow.name}}
Status        : {{workflow.status}}
Duration      : {{workflow.duration}} seconds
Trigger Time  : {{workflow.creationTimestamp}}
Failed Step   : {{workflow.failures}}

Affected Datasets: DEVICE_TELEMETRY / ORDER_EVENTS (Date: 2026-09-17)

Direct Diagnostic Links:
- Centralized Logs: https://kibana.example.com/app/discover#/?_a=(query:(language:kuery,query:'service:"batch-data-extractor"%20AND%20level:"ERROR"'))
- Orchestrator UI : https://argo.example.com/workflows/data-engineering/{{workflow.name}}
======================================================================
Automated alert notification generated by Argo Orchestrator.
```

## 3. Kibana Standard Queries (KQL)

1. **Zero-Row Anomaly Check:**
   ```kuery
   service: "batch-data-extractor" AND stage: "EXTRACT_DB" AND row_count: 0
   ```
2. **Retrieve Failures within 24 Hours:**
   ```kuery
   service: "batch-data-extractor" AND level: ("ERROR" OR "CRITICAL")
   ```
3. **Analyze Database Extraction Performance:**
   ```kuery
   service: "batch-data-extractor" AND stage: "EXTRACT_DB"
   ```

## 4. Disaster Recovery & Incident Runbook

| Incident | Root Cause | Action Plan |
| :--- | :--- | :--- |
| **Alert: Failed at EXTRACT_DB** | 1. Exhausted database connection pool.<br/>2. Query timeout due to large data volumes. | Check Aurora/PostgreSQL CPU and active connection metrics; increase statement timeouts or segment queries. |
| **Alert: Failed at UPLOAD_S3** | 1. IAM Role revoked or KMS permissions invalid.<br/>2. Network S3 Endpoint failure. | Verify ServiceAccount IAM policies and check KMS Key usage limits. |
| **Alert: Failed at POST_WEBHOOK** | 1. JWT token expired or signing secret rotated.<br/>2. Ingress/Kong gateway downtime. | Inspect Kubernetes secrets for JWT keys and verify API Gateway status. |
| **Pod OOMKilled (Exit 137)** | Daily data volume exceeded container memory limits. | Implement server-side cursor streaming in Python rather than loading all rows into memory. |
