# Observability & Monitoring Specification

คู่มือข้อกำหนดการจัดทำระบบติดตาม (Monitoring), การบันทึกเหตุการณ์ (Logging), และระบบแจ้งเตือน (Alerting) สำหรับ Data Pipeline

---

## 1. Structured JSON Logging Specification

สคริปต์ Python ทั้งหมดส่ง Log ออกมาที่ `stdout` ในรูปแบบ **JSON Lines (JSONL)** เพื่อให้ Log Collector (เช่น Fluentbit/Logstash) รวบรวมเข้า Elasticsearch ได้โดยตรง

### JSON Schema:
| Field | Type | Description / Example |
| :--- | :--- | :--- |
| `timestamp` | string (ISO-8601) | `2026-09-18T01:05:23.142Z` |
| `level` | string | `INFO`, `WARNING`, `ERROR`, `CRITICAL` |
| `service` | string | `batch-data-extractor` |
| `dataset` | string | `DEVICE_TELEMETRY` หรือ `ORDER_EVENTS` |
| `stage` | string | `EXTRACT_DB`, `WRITE_CSV`, `UPLOAD_S3`, `POST_WEBHOOK` |
| `batch_id` | string (UUID) | Unique ID ต่อรอบการประมวลผล |
| `export_date` | string (YYYY-MM-DD) | Partition date |
| `row_count` | integer (optional) | จำนวนแถวข้อมูลที่ประมวลผลได้ |
| `duration_ms` | integer (optional) | ระยะเวลาที่ใช้ใน Stage (ms) |
| `message` | string | คำอธิบายสถานะการทำงาน |
| `error_details` | object (optional) | Exception type, message, traceback |

## 2. Argo Workflow `onExit` Email Alerting

ใช้ `onExit` ของ Argo Workflow เป็น Fail-safe จัดการแจ้งเตือนระดับ Container / Pod Lifecycle

### กลยุทธ์การตรวจจับความผิดพลาด:
- **Application Failure:** Database connection error, S3 permission error, API gateway reject
- **Infra Failure:** Pod OOMKilled, Pod Evicted, Pod ActiveDeadlineExceeded

### ตัวอย่าง Email Alert เมื่อ Pipeline ล้มเหลว:
```text
Subject: [ALERT] Batch Data Pipeline Failed: batch-data-extractor-20260918-0100

--------------------------------------------------------------------------------
PIPELINE EXECUTION FAILED
--------------------------------------------------------------------------------
Workflow Name : {{workflow.name}}
Status        : {{workflow.status}}
Duration      : {{workflow.duration}} seconds
Trigger Time  : {{workflow.creationTimestamp}}
Failed Step   : {{workflow.failures}}

Dataset Target: DEVICE_TELEMETRY / ORDER_EVENTS (Date: 2026-09-17)

Direct Links:
- Centralized Logs: https://kibana.example.com/app/discover#/?_a=(query:(language:kuery,query:'service:"batch-data-extractor"%20AND%20level:"ERROR"'))
- Orchestrator UI : https://argo.example.com/workflows/demo/{{workflow.name}}
--------------------------------------------------------------------------------
Automated alert generated by Argo Orchestration Engine.
```

## 3. Kibana Query Samples (KQL)

1. **ตรวจสอบรอบที่ไม่มีข้อมูล (Zero Rows):**
   ```kuery
   service: "batch-data-extractor" AND stage: "EXTRACT_DB" AND row_count: 0
   ```
2. **ค้นหา Error ใน 24 ชั่วโมง:**
   ```kuery
   service: "batch-data-extractor" AND level: ("ERROR" OR "CRITICAL")
   ```
3. **ตรวจสอบเวลาประมวลผล Database Query:**
   ```kuery
   service: "batch-data-extractor" AND stage: "EXTRACT_DB"
   ```
